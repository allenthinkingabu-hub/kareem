## 2. 跨职能泳道图 (Cross-Functional Swimlane Diagram)
> 【视觉核心】面向所有角色，明确"谁、在什么阶段、做了什么操作、产生什么流转"。
> 使用 Mermaid sequenceDiagram 语法渲染，方便版本控制。同时提供 `.drawio` 独立文件。

```mermaid
sequenceDiagram
    autonumber
    actor User as [用户角色] (Client)
    participant UI as 前端/客户端 (UI/UX)
    participant ServiceA as [主服务名称] (Backend - ServiceA)
    participant ServiceB as [依赖服务名称] (Backend - ServiceB)
    participant External as [外部系统名称] (External)

    User->>UI: [步骤1: 触发动作描述 (如：点击发起申请按钮)]
    UI->>ServiceA: [步骤2: 请求描述 (如：POST /api/resource 携带 {field1, field2})]
    
    alt [异常路径1描述]
        ServiceA-->>UI: [返回错误码和错误信息]
        UI-->>User: [向用户展示的错误提示]
    else [正常路径描述]
        ServiceA-->>UI: [返回成功响应]
        UI-->>User: [成功后的页面状态或跳转]
        
        ServiceA->>ServiceB: [异步或同步调用描述]
        ServiceB->>External: [外部系统调用描述]
        
        par 异步处理
            ServiceB-->>ServiceA: [异步回调描述]
        end
        
        alt [回调成功场景]
            External-->>ServiceB: [成功回调内容]
            ServiceB->>ServiceA: [状态更新通知]
            ServiceA->>User: [用户通知 (站内信/邮件/推送)]
        else [回调失败场景]
            External-->>ServiceB: [失败回调内容]
            ServiceB->>ServiceA: [失败状态更新]
            ServiceA->>User: [失败通知及引导操作]
        end
    end
```

> 📎 独立图纸文件：`diagrams/bp_swimlane.drawio`
