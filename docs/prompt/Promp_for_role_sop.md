# Guidelines (核心准则与拔高要求)
我不希望看到一份初级执行者的流水账。这份 SOP 必须体现该角色的“专家级/架构级思考”：
1. **必须包含“防御性思维”**：不仅仅是怎么把活干完，要强制加入异常态兜底、性能劣化防患、以及系统性风险阻断机制。
2. **必须包含“权衡（Trade-off）”**：不局限于一种方案，要在特定阶段要求输出多方案的利弊对比与最终决策。
3. **必须建立“全域依赖网”思维**：
    *   **角色任务 ID**: 每个任务必须分配唯一 ID (格式：`Task-[Role名称简写]-X.Y`)。
    *   **强依赖校验 (Prerequisites)**: 每个任务下必须显式标注其前置依赖项 ID。
    *   **看板对齐 (Registry Binding)**: 任务必须能挂载并反写到全局任务依赖注册表 `context/sop/Project_Task_Registry.md`。
4. **重视上下游链路**：向上要懂业务目标的剖析和输入验证，向下要强调标准化的高质量交付品和闭环的追溯。

# Structure (强制结构约束)
请严格遵循以下 6 个核心阶段（Phase）的骨架进行撰写，并在每个阶段下拆解 3-4 个具体的 Task（任务点名称与执行动作说明）：

*   **Phase 1: 需求基线挂载与本域独立追问 (Context Hook via Shared Board)**
    *   (核心动作：【全新协同铁律】第一步必须强制规定该角色去读取全局任务注册表 `Project_Task_Registry.md` 确认其 Task ID 的 `Prerequisites` 是否全部完成。校验通过后，读取大盘看板 `Master_Context_Board` 剥离共性大局。绝对禁止让该角色去向客户做“背景调查”。该角色只能针对自身专业领域的特异性卡点，遵循“在黑板打上预定义锁 -> 去盘问客户 -> 拿回该领域的刚性方案落入黑板”的自治状态流)。
    *   **⚠️【附加输出要求】**：在输出完这份 SOP 详情后，请你在末尾额外附上一部分。这部分包含两段代码块：
        1. **更新注册表代码块**：使用 `multi_replace_file_content` 工具，自动将本次生成的所有新任务（Task ID, Name, Prerequisites）以表格行的形式追加到 `context/sop/Project_Task_Registry.md` 末尾，状态设为 `[WAITING]`。
        2. **更新大盘模板代码块**：脑暴一个专属于该新角色的、极具专业深度的尖锐提问示例，并用 `[待解决] @[该新角色名]：发出的极客问题...` 的格式写出来。
*   **Phase 2: 现状摸底与盘点排雷 (As-Is Audit & Discovery)**
    *   (核心动作：针对现有代码、数据、旧流程或历史包袱进行盘点、寻根和发现技术债/视觉债)
*   **Phase 3: 方案推演与架构决策 (Exploration & Decision)**
    *   (核心动作：针对本角色的专业领域，提出 2-3 个备选解决路径，做多维权衡对比并做出最终采用决策)
*   **Phase 4: 蓝图绘制与详细实现设计 (Detailed Solution Design)**
    *   (核心动作：本角色核心的“画图纸”阶段，精准阐述实施落地的核心结构、正向链路流转与特定工序说明)
*   **Phase 5: 风险阻断与边界兜底管控 (Risk & Blast Radius Assessment)**
    *   (核心动作：从特有专业角度提出极端边界测试项、性能劣化排查、断网/死机/高并发等异常形态的降级与应急预案)
*   **Phase 6: 工程质检交付与实施追踪 (Quality Handoff & Implementation)**
    *   (核心动作：面向下游如何移交标准的输出物？如何进行专业的验收走查？上线后的跟进与数据验证)
