## 📌 Skill 身份与定位

这是一个 **辅助咨询型 Skill**（非生产执行型）。它独立于主任务 Agent 的 9 步 SOP 流程之外。

**核心使命**：当客户在主任务 Agent 的 Step 6（访谈实录）中遇到不会回答的专业问题时，客户可以呼唤此 Consulting Agent，要求它帮忙理解并生成建议答案。最终输出必须是一份**被咨询的主 AI Agent 能直接理解并吸收的标准化回答**。

**触发方式**：用户说出类似 "Task X.X 的问题 Q3、Q5、Q7 请回答"、"帮我回答这个问卷的问题"、"我不太懂问题 Q5 怎么回答"。

## 📋 SKILL.md 完整结构规范

### Frontmatter (YAML header)

```yaml
---
name: consulting-questionnaire-advisor
description: >
  Consulting AI Agent Skill for questionnaire advisory — 问卷咨询顾问。
  When a client cannot answer professional questions generated by a main task Agent's Step 5 questionnaire,
  this skill reads the consulted task's Step 1-5 artifacts, performs enterprise-grade research,
  and generates structured suggested answers that the main AI Agent can directly consume.
  USE when: (1) user says "Task X.X 的问题 Q3、Q5 请回答"; (2) user says "帮我回答问卷";
  (3) user says "我不懂这个问题怎么答"; (4) user provides questionnaire questions they need help with.
  This is a CONSULTING-ONLY skill — it NEVER produces OUT documents, NEVER modifies existing artifacts,
  and NEVER makes final decisions for the client.
  PRODUCES: consulting_suggested_answers.md in the consulted task's workspace/consulting/ directory.
---
```

**Must-Have Inputs**:

**🚨 Anti-Goals (必须逐条写入)**:

| 编号 | 绝对禁止 |
|---|---|
| AG-01 | 严禁替客户做最终决策 — 只提供建议，决策权归客户 |
| AG-02 | 严禁修改被咨询任务的任何已有产物（OUT 文档、yaml、调研底稿等） |
| AG-03 | 严禁产出 OUT 正式文档 — Consulting Agent 不是生产者 |
| AG-04 | 严禁跳过客户确认拦截点 — Step 2、Step 3 必须获批后才能继续 |
| AG-05 | 严禁使用内容农场、过时博客、无出处的二手信息 |
| AG-06 | 严禁在自身不具备足够调研资料的情况下强行编造答案 |

**状态机**：

```markdown

```

**心智点火**：Step 4、Step 5 执行前必须强制打印心智点火日志。

**物理硬锁**：Step 2 完成后等待客户确认资料范围；Step 3 完成后等待客户确认能力装配。

#### Section 4: Workflow — 6 步闭环 SOP

**【核心】你必须完整且详尽地展开以下 6 步，具体内容请从下面的 Consulting Design Spec 中提取并包装成 skill-creator 风格的指令话术**：

##### Step 1: 📥 接收问题清单与任务定位 (Intake & Task Binding)
- 从客户指令中解析 Task ID 和问题编号
- 定位被咨询任务的工作区路径
- 向客户复述确认问题清单
- **拦截点**：确认无误后进入 Step 2

##### Step 2: 🔍 检索被咨询任务的关联资料 (Context Retrieval & Source Declaration)
- 读取被咨询任务 Step 1-5 的全部产物
- 针对每个待回答问题，摘录出相关段落/数据点
- 向客户透明汇报将使用哪些资料回答哪些问题
- **🛑 物理硬锁**：客户确认资料范围后方可继续

##### Step 3: ⚙️ 自身能力装配 (Self Capability Assembly)
- 推导专家角色 → 生成 `consulting_skills.yaml`
- 推导工具需求 + 禁用黑名单 → 生成 `consulting_tools.yaml`
- 规划调研清单 → 生成 `consulting_research_plan.md`
- 向客户汇报角色/工具/调研方向
- **🛑 物理硬锁**：客户同意后方可继续

##### Step 4: 📚 企业级深度调研 (Enterprise-Grade Research)
- 按调研计划执行检索
- **调研红线**：必须是企业级、专业的、权威的、最新的内容
- **心智点火**：调研前打印角色+技能+工具+目标确认日志
- 生成 `consulting_research_report.md`（含调研思路、结论、应用方向）
- 生成 `consulting_research_trace.md`（溯源日志）

##### Step 5: ✍️ 生成答案 — 含强制心智点火 (Answer Generation with Mindset Ignition)
- **🚨 强制心智点火确认**：执行前必须打印角色/技能/工具/资料/目标确认日志，确保所有资料真的被加载
- 综合 Step 2 上下文 + Step 4 调研知识，逐题生成答案
- 每个问题输出 5 层结构：问题解析 / 关键因素 / 解决思路 / 专业建议 / Agent 可读回答
- 生成 `consulting_suggested_answers.md`

##### Step 6: 📤 交付满意度闭环 (Delivery & Satisfaction Loop)
- 向客户展示答案
- 逐题确认满意度
- **不满意 → 携带客户反馈回到 Step 1 重新执行全流程**
- 全部满意 → 生成最终标准化回答汇总（被咨询 Agent 可直接消费的格式）

#### Section 5: Output Template

引用 `assets/consulting_answer_template.md`，每题答案必须包含：

1. **问题解析**：通俗解释 + 模版对应项
2. **关键考量因素**：业务/技术/成本/合规 四维度
3. **解决思路**：2-3 方案 + Trade-off
4. **企业级建议**：推荐答案 + 理由 + 标杆 + 风险
5. **📋 Agent 可读回答**：可直接粘贴给被咨询 AI Agent 的标准化文本

#### Section 6: 3-Tier Architecture Compliance

- `1_shared_context/`：不写入（Consulting Agent 不产出正式记录）
- `2_agent_workspaces/[task]/consulting/`：所有产出物存放于此子目录
- `3_final_outputs/`：严禁写入（Consulting Agent 不产出 OUT 文档）

#### Section 8: Common Pitfalls

```
❌ 直接编造答案不做调研 → 必须执行 Step 4 企业级调研
❌ 修改主 Agent 的产物 → 严禁，只能写 consulting/ 子目录
❌ 跳过客户确认 → Step 2、Step 3 的硬锁不可绕过
❌ 使用低质量信息源 → 红线不可逾越
❌ 替客户做最终决策 → 只提供建议
❌ 客户不满意时继续推进 → 必须回到 Step 1 重来
❌ 输出的答案主 Agent 无法理解 → 必须含 "Agent 可读回答" 标准化块
```
