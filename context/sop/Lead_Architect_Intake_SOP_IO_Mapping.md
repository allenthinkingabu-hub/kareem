# 总控大脑 SOP 输入输出映射表 (Lead_Architect_Intake_SOP_IO_Mapping)

本文档是针对《定向破冰总架构师 SOP (Lead Architect Intake SOP)》的专用 I/O 流转地图。它精准定义了在该项目的最早期阶段（极大不确定性时期），总控角色是如何将离散的外部输入（客户语料）逐步收敛，并最终熔铸为下游所有 Agent 所依赖的骨干源头 —— “共享大盘黑板”的。

---

## 术语库与节点流转约定

*   **[EXT-XXX] (外部极光输入/输出)**：指代由人类客户提供、或者由外部系统直接透传的原始变量，抑或是最终输出到整个 AI 引擎共享区供百花齐放的全局资产。
*   **OUT-0.X (中转缓存栈)**：指代该总控 Agent 在问客打草稿时产生的内部推演节点。

---

## Phase 0: 需求破冰与大盘基准初始化 (Global Context Intake)

**阶段使命**：一次性、高密度的集中访谈，将原本混沌的需求提炼为结构化的全局状态墙，作为整个项目生态唯一的上下文起跳点。

### Task 0.1: 挖掘核心意图与最高商业诉求
与客户强对接，梳理出为什么要做这套系统、必须伺候好的买单受众群体，以及系统必须达成的商业刚需。

*   **入参 (Inputs)**:
    *   `[EXT-Topic/Idea]`：客户最初的一句话需求或发散的想法。
    *   `[EXT-Business_PRD]`：客户可能提供的残缺/初版的商业逻辑文档（若有）。
*   **出参 (Outputs)**:
    *   `OUT-0.1`：高纯度清洗后的核心商业指标与受众画像特征库（内部缓存态）。

### Task 0.2: 探测系统极值水位线
逼问客户量级天花板（预计 DAU、峰值大盘 TPS）、不可被妥协的设备延展度及生死攸关的时间、法务底线。

*   **入参 (Inputs)**:
    *   `[EXT-Topic/Idea]`：用于界定逼问的边界范围。
    *   `OUT-0.1`：基于上一步得出的商业人群去估算最大化的系统承载天花板。
    *   `[EXT-Client_Dialogue]`：该步骤中实时的多轮逼问 QA 实录。
*   **出参 (Outputs)**:
    *   `OUT-0.2`：全局非功能性约束 (Global NFR) 和底线红线列表。

### Task 0.3: 初始化首位活体黑板 (Init Blackboard)
以无歧义的文本，将上述共识结论写成标准化的具体大盘实例，并进行全局物理落盘。

*   **入参 (Inputs)**:
    *   `OUT-0.1`：清洗后的核心商业指标与受众画像特征。
    *   `OUT-0.2`：全局非功能性约束与红线列表。
    *   `[EXT-Master_Context_Board_Template.md]`：作为注入这些数据的标准外壳/骨架。
*   **出参 (Outputs)**:
    *   🔥 **`[EXT-Master_Context_Board.md]` (最终神圣产物)**：落地于项目根目录。一旦它被实例化生成，即刻向全时总线宣告 Phase 0 闭环。它的诞生直接触发整个架构链路的下游（后端、前端、UI/UX）集体抢占资源入场。
    *   `[EXT-Meeting_Records]`：将前两个步骤中长篇大论的唠嗑实录，打包装存进 `1_shared_context/meeting_records/` 目录中，供后人凭吊/检索。
