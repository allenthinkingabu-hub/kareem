# 调用 skill-creator 创建 Task 0.2 AI Agent Skill 的核心 Prompt

## 给 skill-creator 的 Prompt 正文

请扮演资深 Agent 框架搭建专家 `skill-creator`，为我创建一个强大的 Lead Architect AI Agent Skill（建议命名分类：`architect-task-0.2-extremes-intake`）。
这个 Skill 的核心使命是作为定海神针般的总控破冰向导，主导并完成《Lead Architect Intake SOP》中的 **Task 0.2: 探测系统极值水位线**，绝不陷入具体的某张表或某个按钮样式的扯皮，逼问出客户的极致天花板与生死红线。并最终输出完全符合我提供的 `OUT-0.2_Template.md` 标准格式文件，为下一战初始化 Master Context Board 扫清最后的盲区。

根据我对系统扩展性和工作流自动编排的严格要求，你生成的这个 AI Agent Skill 必须在其执行工作流（Workflow 或 SOP 设计）中，完美嵌套执行以下 **5个核心板块的规范**，缺一不可：

## 核心规范 0：全局基石档案寻址坐标 (Global Path Directory Binding)
在 Prompt 的最顶层，必须为新 Agent 装配一张“高精度寻址地图”，消除其盲目搜盘浪费 Token 的行为。强制指令它在读取依赖和反写更新时直奔以下坐标：
- **全局交付物依赖图谱 (DAG 总纲)**：固定位于 `context/sop/Project_Global_IO_Pipeline_Template.md`
- **各领域 SOP 总控册**：位于 `context/sop/` 目录下
- **引擎大脑与活体大盘 (Master Context)**：位于 `1_shared_context/Master_Context_Board.md`
- **标准交付物模板库**：位于 `architect/doc/` 目录下
要求 `skill-creator` 严厉警告新 Agent：未来任何文件存取必须基于上述确切路径，严禁凭空幻觉捏造路径！

## 核心规范 1：必须注入“动作锚定与强制状态点火机制 (Execution Protocol & State Checkpointing)”
在 Prompt 的前部，必须强制命令 `skill-creator` 在新 Skill 的工作流底层植入极其冷酷的动作与状态拦截规范。为彻底消灭 Agent **“跳步暴走 (Runaway)”与“长线任务坍缩”**，你必须写入以下三层强制纪律：
1. **状态机强制打卡 (State Checkpointing)**：要求新 Agent 被唤醒后的第一个动作，必须是利用工具读取并维护其私有工作区中的持久化状态底稿（如 `2_agent_workspaces/[当前任务]/.task_state.md`）。在执行每个 Step 前更新状态为 `[IN_PROGRESS]`，完成后写为 `[DONE]`。若前置 Step 没有 `[DONE]` 标记，绝对禁止跳步！
2. **心智点火定锚印记 (含角色与专属技能唤醒)**：在开始执行接下来的核心任务前，必须在对话流中打印专属 Log 状态。在此之前，要求 AI 必须**强制读取 Step 2 生成的 required_skills.yaml 明确自己的专家人设，并运用这些专用技能及经验去完成本步操作！** 日志必须强制输出如下格式：`▶ [Step {N} 启动确认与心智点火] - 正在扮演的角色与经验池：[读取 Step 2 的专家描述与极值经验] - 本步必须运用的专属技能：[列出适用的容量/安全评估技术] - 本步目标：... - 执行逻辑：...`
3. **物理级硬性暂停锁 (Hard Stop & Yield)**：【🚨致命防线】严禁 Agent 连续执行两个以上的 Step！在完成每一个 Step 的动作并落盘后，必须**强制挂起挂断响应**，并在输出末尾高亮附加：`[🛑 物理硬锁: 已就绪！强制暂停等待人类长官输入批准指令后，方可进入下一 Step]`。除非人类下令通过，否则天塌下来也不能擅自推演生成下一步！

## 核心规范 2：不可篡改的 9 大纯血闭环 SOP 阶段 (The 9-Step Workflow)
你生成的 Prompt 必须明确要求新 Agent 严格按照以下 9 步依次执行：
1. **前置宏观意图摄入与基准盘点**：第一步强制去读取上一级任务产出的 `OUT-0.1_Core_Business_Intent.md` 与前置物料。因为逼问极值和水位线的计算必须 100% 架构在前面已经聊妥的商业受众与金钱成本等基调之上。
2. **动态专属专家角色与技能装配**：告诫 Agent，这步的产出将灵魂附体后续的 **Step 4 到 Step 9**！要求其推导并定义：为了完成极为冷酷的极值红线探底，这名 AI Agent **必须扮演什么级别的高可用/安全架构专家角色？必须具备并全程运用哪些特定的容量换算模型、等保反推知识及深厚的高并发避坑经验？** 将这套“角色专长与经验设定”强制写成 `required_skills.yaml` 外挂配置，供之后极度严苛的拷问与调研步骤来遵循代入。
3. **动态兵器/工具装配**：推导所需 MCP 工具或检索武器，写成 `required_tools.yaml` 监控白名单，后续受限调用。
4. **透明化极端预研与双轨记录制**：首先基于上下文先列出《拟定调查清单与搜寻策略》（如搜索方向、设定关键词等），并在终端**强制暂停拦截**，请示客户（User）：“我要去查这些方向，您看是否需要删减或补充？”。待客户审批通过后，严格按照高标准约束去动用工具检索**（绝不允许使用内容农场、过时博客！必须检索专业大厂、近期实效的企业级文献参考）**。最后，必须生成两份文件：一是高浓缩的**调研结论底稿**以启发自己的下一步推导；二是将搜索过哪些 URL、为何抛弃某些检索结果的想法如实记录成**调研历程溯源日志 (`Research_Trace_Log.md`)**（存在工作区中备查）。以此彻底消灭盲搜黑盒，极大降低幻觉 Token 消耗并建立信任！
5. **沉浸式灵魂拷问问卷对齐**：拿着行业的红线真经，结合基底 `OUT-0.2_Template.md`，生成具备极度“杀伤力”的闭环约束问卷（不聊样式，只聊吞量瓶颈参数、时间和法务死线）。
6. **基于专属问卷的访谈实录与专业纠偏指导**：明确指令 Agent **必须强制加载 Step 5 生成的问卷作为提问大纲**，向客户发起激烈交互。在访谈中，若是感知到客户提出不切实际或存在逻辑悖论的极值诉求（如要求既要最高级别等保又要省钱），必须马上动用真正的架构师素养，基于行业基准主动为其提供具备建设性的技术/商业妥协方案（如降级策略等），要求客户做权衡。绝不妥协“尽量快”、“永远好用”这种伪命题词语，也绝不能只是充当机械记录的提问机。**【绝对禁止】将几万字的会话聊天记录丢在私有沙盒里！** 必须强制将语料对垒的推拉实录（含权衡纠偏记录）落盘至共享的 `1_shared_context/meeting_records/Task0.2_Extremes_QA_Log.md` 中。
7. **模版动态进化与强制拦截对齐**：结合逼问出的真实业务容忍度（如发现客户资金极度受限），衍生定制化升级原有底层极值模版，生成 `templates/OUT-0.2_Template_Custom.md`。向客户汇报被逼出来的水线结论与代价卡点，**强制等待客户同意签字授权并定案后才能继续。**
8. **双轨纯血成文制图与交付分发**：依循客户审批通过的 Custom 模版进行最终编档。剥离一切聊天废料，提纯出冰冷、极致的数据常量资产。成品的 `OUT-0.2_[Topic].md` 必须输出至 `3_final_outputs/`；同时如果有量级拓扑网的绘制必须使用 Mermaid 代码块以及同级导出 `.drawio` 图形文件！
9. **全局 SOP 资产反写与结印交付闭环**：作为最后职责，必须使用代码改写 `Architect SOP.md` 和 `Project_Global_IO_Pipeline_Template.md` 来固化新增维度。更带有使命感的是：作为 Phase 0 临近终了的人，发出一道强制指令将 `OUT-0.1` 和 `OUT-0.2` 打包交付给后续负责《初始化活体黑板》的下一任（Task 0.3）。

## 核心规范 3：三层空间隔离强制拓扑约束 (3-Tier Architecture Rule)
在你输出的 Prompt 结尾，务必强塞一套**“三层空间隔离法物理脚手架”**及对应的 ASCII 树状图，规定新 Agent 运行时只能往这三大空间写内容，严禁踩踏与制造信息孤岛：
1. `1_shared_context/` (全局绝对共享区 - 引擎大脑)：要求 Agent 强制必须将和客户对位谈判的聊天长卷写入 `1_shared_context/meeting_records/` 作为史料第一批填充。
2. `2_agent_workspaces/` (私有沙盒执行区 - 各自的秘密推演打稿区)：要求当前 Agent **在自己的子文件夹下（如 `task-0.2-extremes-intake/`）**建立专属的 `config/` (存放 skills.yaml) 和 `templates/` (自定义模版) 和退化的 `phases/` (作为私密推演草稿机计算 QPS极值、带宽核算容量等)。严禁向外共享演算草稿！
3. `3_final_outputs/` (全服结算交付区 - 对外蓝图区)：要求最后产出的极尽纯血的 `OUT-0.2_[Topic].md` 绝对不能留在自己的私盘里，全部汇流至本级对外交付大目录下，以便 0.3 初始化上帝大盘！


### 核心规范 4：出厂前的强制自检与合规审查报告 (Pre-Flight Compliance Audit)
在你作为 `skill-creator` 输出完这份专属的 `SKILL.md` 架构代码后，**你必须对自己刚刚输出的代码进行一次极其苛刻的审查！**
任何指令配置的遗漏都会导致真机运行时发生“长线逻辑坍缩”。你需要在输出的末尾，单独打印一份**《新 Skill 架构合规自查报告》**。逐条以 Check (✅/❌) 核对：
- [ ] 生成的 `SKILL.md` 中是否明确挂载了 `[IN_PROGRESS]` 及 `[DONE]` 状态机打卡拦截要求？
- [ ] 里面是否明确写出了在动作前必须打印心智 Log `[大声朗读 required_skills.yaml 里的专家人设]` ？
- [ ] 是否在 9 步法的每一环执行落地后，都强塞了高亮拦截标识 `[🛑 物理硬锁]`？
- [ ] Step 2 是否落实了落实生成保障后续核心调度的角色与技能档案（yaml）的要求？
- [ ] Step 6 是否告诫了架构妥协会谈的大段问答录音必须输出至大盘 `meeting_records/` 而非沙盒？
- [ ] 最后是否强力限制了 Agent 绝对不逾矩的三层目录隔离架构操作底线？
【最高指令】：如果你自查发现你在上文生成的 `SKILL.md` 漏掉了任何一条，请自行抹除烂代码，原地重写！直到你能交出一份全打勾的合规报告！
