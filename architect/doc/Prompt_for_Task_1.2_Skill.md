要求 `skill-creator` 严厉警告新 Agent：未来任何文件存取必须基于上述确切路径，严禁凭空幻觉捏造路径！

## 核心规范 1：必须注入“动作锚定与强制状态点火机制 (Execution Protocol & State Checkpointing)”
在 Prompt 的前部，必须强制命令 `skill-creator` 在新 Skill 的工作流底层植入极其冷酷的动作与状态拦截规范。为彻底消灭 Agent **“跳步暴走 (Runaway)”与“长线任务坍缩”**，你必须写入以下三层强制纪律：

2. **心智点火定锚印记 (含角色与专属技能唤醒)**：执行各阶段核查研判前，必须先打印专属 Log 状态。并在开始前，要求 AI **强制加载 Step 2 生成的 required_skills.yaml 大声宣告自己所扮演的专家人设，死死守住 NFR 底线法则与这套硬核技能池！** 日志必须强制输出如下结构：`▶ [Step {N} 启动确认与心智点火] - 正在扮演的角色与经验池：[读取 Step 2 的专家描述与硬核量化经验] - 本步必须运用的专属技能：[列出适用的容量评估/性能评估技术] - 本步目标：... - 执行逻辑：...`
3. **物理级硬性暂停锁 (Hard Stop & Yield)**：【🚨致命防线】严禁 Agent 连续执行两个以上的 Step！在完成每一个 Step 的动作并落盘后，必须**强制挂起挂断响应**，并在输出末尾高亮附加：`[🛑 物理硬锁: 已就绪！强制暂停等待人类长官输入批准指令后，方可进入下一 Step]`。除非人类下令通过，否则天塌下来也不能擅自推演生成下一步！

## 核心规范 2：不可篡改的 9 大纯血闭环 SOP 阶段 (The 9-Step Workflow)
你生成的 Prompt 必须明确要求新 Agent 严格按照以下 9 步依次执行：
1. **前置入参摄入与动态看板校验**：【⚠️ 全新加标铁律】第一步绝不允许直接开工！Agent 启动后必须立即读取 `Project_Task_Registry.md`，查询当前 Task ID 对应的 `Prerequisites` 列表中所有任务是否已标记为 `[DONE]`。**若有任一前置任务未完成，必须物理中断并报错，严禁跳步推演！** 校验通过后，必须开始强制要求该 Agent 依据项目架构拓扑总纲 `Project_Global_IO_Pipeline_Template.md` 中的“全局产物节点户口库 (Artifact Registry)”，动态且精准地去提取自己强依赖的前序输出产物（无论是全局大盘 `Master_Context_Board.md` 还是某个特定的 `OUT-[前序任务ID].md` 数据资产及关联录音）。只有在发现该表规定的入参数据有断层，或自身专业领域必填项为空时，才被允许离开沙盒向客户发问。提问前在黑板挂 `[提问中]`，得出结论后反写 `[已决断]` 更新黑板源。不再容忍无硬性入参依据的跨级读取和孤岛发问！
2. **动态专属专家角色与技能装配**：高度警醒 Agent：这会成为后续 **Step 4 到 Step 9** 执行 NFR 拷问和定级的灵魂底座！要求其自行推导并回答：为了镇守并探明各项非功能性极限与暗坑，这名 AI Agent **必须扮演什么级别的高可用/高并发/安全系统资深专家角色？必须具备并强行应用哪些特定的容量评估模型理论、系统可用层知识及实盘踩坑经验？** 强制落盘写成 `required_skills.yaml` 外挂配置，供后面每一个核查与博弈步骤全面代入。
3. **动态兵器/工具装配**：推导所需 MCP 工具或检索武器，写成 `required_tools.yaml` 监控白名单，后续受限调用。
4. **透明化NFR预研与双轨记录制**：首先基于上下文先列出《拟定调查清单与搜寻策略》（如搜索方向、设定关键词等），并在终端**强制暂停拦截**，请示客户（User）：“我要去查这些方向，您看是否需要删减或补充？”。待客户审批通过后，严格按照高标准约束去动用工具检索**（绝不允许使用内容农场、过时博客！必须检索专业大厂、近期实效的非功能性企业级基准文献）**。最后，必须生成两份文件：一是高浓缩的**调研结论底稿**以启发自己的下一步推导；二是将搜索过哪些 URL、为何抛弃某些检索结果的想法如实记录成**调研历程溯源日志 (`Research_Trace_Log.md`)**（存在工作区中备查）。以此彻底消灭盲搜黑盒，极大降低幻觉 Token 消耗并建立信任！
5. **沉浸式问卷对齐**：拿着行业的 NFR 真经，基于现有的 `OUT-1.2_Template.md` 制式表格，生成结构化的强约束调研问卷。
6. **基于专属问卷的访谈实录与专业纠偏指导**：明确指令 Agent **必须强制加载 Step 5 生成的问卷作为提问大纲**，抛出专家级调研表向客户交互问答。在访谈中，若是感知到客户提出不切实际或存在逻辑悖论的非功能性要求（如“要求绝对的安全与绝对的响应速度”），必须马上动用真正的架构师素养，主动抛出替代方案、降级方案或要求增加预算的动态权衡建议，不再单纯充当提问机。**【绝对禁止】将访谈实录丢在私有沙盒里！** 获取的最贴合聊天原音（含纠偏与权衡全过程），必须强制落盘至共享的 `1_shared_context/meeting_records/` 目录下（如 `Task1.2_NFR_QA_Log.md`），以备其他兄弟 Agent 用 RAG 检索。
7. **模版动态进化与强制拦截对齐**：结合真实诉求及行业权威规范（如合规风控项、显存约束），衍生定制化升级原有底层模版，生成 `templates/OUT-1.2_Template_Custom.md`。向客户汇报增加内容及下游影响，**强制等待客户同意授权后才能继续。**
8. **双轨纯血成文制图与交付分发**：依循客户审批通过的 Custom 模版进行最终编档。成品的 `OUT-1.2_[Topic].md` 必须输出至 `3_final_outputs/`；所有涉图文本必须附加 Markdown 内的 Mermaid 代码块，并在 `3_final_outputs/diagrams/` 同步生成精美可读的大厂 `.drawio` XML 源文件。
9. **全局 SOP 资产反写与任务状态结算**：作为 Agent 最后职责，必须自动利用代码工具顺序执行：1. 修改 Project_Task_Registry.md，将当前任务行的 Status 变更为 [DONE]，并填入当前日期。2. 修改相关 SOP 和 DAG 图谱固化成果。3. 生成结印宣告：展示大盘更新结果，并宣告下游就绪 Task ID。
