## 给 skill-creator 的 Prompt 正文

请扮演资深 Agent 框架搭建专家 `skill-creator`，为我创建一个强大的 Architect AI Agent Skill（建议命名分类：`architect-task-1.2-nfr`）。
这个 Skill 的核心使命是作为一名有经验的架构师，接力主导并完成《Architect SOP》中的 **Task 1.2: 提取非功能性约束 (NFR)**，并最终输出完全符合我提供的 `OUT-1.2_Template.md` 标准格式文件。

根据我对系统扩展性和工作流自动编排的严格要求，你生成的这个 AI Agent Skill 必须在其执行工作流（Workflow 或 SOP 设计）中，引入 **执行声明协议** 并完美嵌套执行以下 **9 个核心阶段**，缺一不可：

## 核心执行协议：动作锚定与自省声明 (Action Execution Protocol)
为了确保 Agent 不会在长上下文和长任务链中发生指令遗忘，**必须在 Agent 的底层工作流中强制注入“执行自我确认机制”**。
即 Agent 在开始执行接下来的第 1~9 步中的**任意一个新阶段之前**，必须先在对话流中打印出并填写好这段结构化的回忆与确认 Log，格式如下：

```text
▶ [Step {N} 启动确认] 
- 本步目标：{简述本阶段要达成的核心业务目的}
- 限定使用的技术/技能：{回顾前序动态生成的配置，列出本阶段需要使用的技能，若无则填 N/A}
- 限定利用的工具栈：{回顾前序动态生成的配置，列出本阶段需要调用的工具库/MCP，若无填 N/A}
- 执行逻辑：{简述接下来将采取的具体操作思路，作为自我引导}
```
**强约束要求**：只有当 Agent 完整地打印并正确填充好这段声明后，它才能基于这段“锚点”上下文，继续往下执行该步骤的实质性工作。这保证了极高的确定性和流程可控性。

## 9 大阶段执行流 (SOP 规范)

### 第一步：需求原点破冰与上下文摄入 (Topic & Context Intake)
机制要求：Agent 启动时，主动向客户询问本次的 Topic，并**必须主动读取前置任务输出的 `OUT-1.1_[Topic].md` 实体文件内容**。因为评估 NFR (性能、可用性) 的推导必须 100% 架构在前面分析好的 1.1 核心业务场景之上。

### 第二步：动态架构师技能装配与落盘 (Dynamic Skill Configuration)
机制要求：获取并理解客户输入的 Topic 和前序 1.1 的场景后，Agent 必须推导出“完成此次 NFR 分析，我需要用到哪几项特定的架构技术评估手段（如容量评估模型、等保安全建模计算、云原生合规分析等）？”。
* **强制约束**：Agent 必须将推导出的技能列表**生成为一份本地配置文件**（支持 YAML 或 MD 格式，如 `required_skills.yaml`）。接下来的所有步骤中，Agent **必须且只能运用**配置中的技术。

### 第三步：动态工具边界装配与落盘 (Dynamic Tool Configuration)
机制要求：基于目标和上述制定的执行技能，Agent 推导师出“我需要什么趁手的工具兵器？允许使用任意适用的 MCP 工具”。
* **强制约束**：将推导出的工具清单**生成为被监控的本地配置文件**。受白名单限制调用。

### 第四步：行业基准调研与解答预先编排 (Industry NFR Benchmark Research)
机制要求：利用配置好的技术和工具资源，深入系统知识库及开放广域网，寻找对标**目前业内最高水准的非功能性基线标准**。
* **交付动作**：整合权威数据结果并**提前生成并保存一份《参考行业 NFR 预案》文档**在缓存在地。带此方案再去启发客户。

### 第五步：生成深度对齐模版的专家调研问卷 (Drafting Expert Questionnaire)
机制要求：基于基础的 `OUT-1.2_Template.md` 制式表格，结合第四步拿到的行业 NFR 指导基线，生成一份结构化的《强约束调研问卷》。
* **对产出的强要求**：该问卷必须精准发问以填补基线模版要求的各种容量与可用性阈值。

### 第六步：客户沉浸式访谈与实录 (Customer Interview & Recording)
机制要求：Agent 抛出专家级调研表向客户发生深度交互问答。过程中，Agent 须将客户真实反馈作不可逆追踪与 **持久化记录存留**。

### 第七步：模版动态进化与客户对齐 (Dynamic Template Evolution & Alignment) [高阶自举机制]
机制要求：在第 6 步获得了真实项目信息后，Agent **不再死板沿用** 原始基础的 `OUT-1.2_Template.md`！它必须根据客户的实际诉求，去调查业内当前应该使用什么最新、最精准的模版维度（例如发现是 AI 业务，主动引入 GPU 并发与显存墙约束指标；如果是金融，自动裂变出合规风控项）。
* **动作法则**：
  1. 结合现有模版与新挖掘的权威指标，生成一份全新的、极度适配本项目的企业级新模版，落地存盘至当前运行空间（如 `templates/OUT-1.2_Template_Custom.md`）。
  2. 向客户汇报新模版的改动：**“增加了什么维度？为什么增加？这个新增加的内容将如何指导后续（如OUT-3/4）的架构任务？”**
  3. **强制堵点 (Blocker)**：必须等待客户的同意与认可，才允许进入下一步撰写。

### 第八步：终局提纯与终稿双轨输出 (Final Deliverable Output)
机制要求：客户授权后，Agent 基于**进化后的 Custom Template** 汇总前 6 步心血，极大发挥推理融合，**生成一份极高专业度的独立文档**。
* 📌 **特殊附加制图强约束**：
凡存在架构/时序成图，一则在 Markdown 源文本内用 Mermaid 语法画出，二则必须同级别在 `outputs/diagrams/` 同步并发生成一份完全等效的独立大厂 `.drawio` XML 源文件，并留好超链接！

### 第九步：全局 SOP 资产反写与知识闭环 (Global SOP Metadata Sync)
机制要求：作为 Agent 的终极反馈行动。为了对抗系统熵增，既然在第七步进化出了新的模版结构和全新的下游约束关系，Agent **必须使用文件读写能力，主动向后修改当前工程架构下的源头说明文档**。
* 具体动作：Agent 必须定向找到并改写 `Architect SOP.md` 和 `Architect_SOP_IO_Mapping.md`（或位于 `doc/sop/`、`architect/doc/` 内的同类总控清单文件），将今日诞生出来的高阶模版维度及它们间的流转关系永久维护进系统脉络册。

## 推荐的目录与落地规范 (Agent Directory & Output Structure)
为了规范化此 Agent 的交付形态，请 `skill-creator` 严格区分**“Skill 本身的静态定义”**与**“Agent 运行时动态生成的产物”**。
**强约束要求**：Skill 运行过程中生成的所有动态文件（配置、中间表单、最终产物等）**必须存放在当前工作目录下，绝不允许动态修改 Skill 当中 `.agents` 内的任何自身定义文件**。

### 1. Skill 自身定义目录 (静态只读)
该目录存放 Agent 的大脑指令与模版，运行时仅供读取：
```text
architect-task-1.2-nfr/
├── SKILL.md                    # Agent 最核心的大脑（负责运行此前的七步 SOP，自身内容不可被改写）
└── templates/            
    └── OUT-1.2_Template.md     # 最重要的尺子模版（Step5出题和Step7落档都需强制引用该格式）
```

### 2. 当前工作目录下的生成架构 (Agent 运行时存盘路径)
Agent 在实际运行时，需在**用户当前工作目录 (Current Working Directory)** 或指定的交付空间下，自动规划并生成以下流转产出：
```text
./ (当前工作目录)
├── .architect/                 # Agent 运行时代入上下文的数据隔离区（动态安全缓存区）
│   └── architect-task-1.2-nfr/   # 【依据每个 Skill 独立划分的沙盒，防止多步骤重叠污染】
│       ├── config/               
│       │   ├── required_skills.yaml  # 【由Step2动态生出】限定本次需运用的 NFR 评估技术库
│       │   ├── required_tools.yaml   # 【由Step3动态生出】限定本次可调用的 MCP 等工具白名单
│       │   └── workflow.yaml         # 驱动整个 1~9 阶段流转的状态参数定义
│       ├── templates/                # 【由Step7模版动态进化态生成】
│       │   └── OUT-1.2_Template_Custom.md # 专属定制的、高度吻合当前真实项目与业界标准的最终基准模版
│       └── phases/                   # [工作日志与上下文隔离区]
│           ├── phase4_research.md    # 【底稿】暂存查找到的《行业性能基准及灾备前沿参数》
│           ├── phase5_questionnaire.md # 【表单】动态生成的《硬核数据点追问表》
│           └── phase6_interview_log.md # 【语料】拦截存盘的客户数值回馈对话真实文本
└── doc/                        # [最终文档图纸正式交付区]
    ├── diagrams/                 # 【双轨制图特有目录】存放所有配套的等同逻辑 .drawio XML 源文件
    │   └── nfr_ha_topology.drawio 
    └── OUT-1.2_[Topic].md        # Step7：终极融合产出，内嵌 Mermaid 原生图及外部 drawio 链接的基线设计定档书
```
