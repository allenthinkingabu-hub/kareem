# UI/UX 设计师 SOP (Standard Operating Procedure)

本文档定义了作为高级 UI/UX 设计专家，在接到一个全新产品需求或功能迭代时的标准操作流程。这是一份端到端 (End-to-End) 的执行框架，确保设计不仅停留在视觉表层，更能贯穿业务目标、体验逻辑与最终的工程落地。

---

### Phase 1: 共性基线吸纳与体验目标锚定 (Intake via Shared Board)
**目标**：不白手起家问客户，而是基于全业务视角的先验输入，直接锚定体验设计的靶心与约束边界。
*   **Task 1.1: 承接全局大盘看板画像**：读取项目根目录的活跃资产 `[EXT-Master_Context_Board]` 定位大目标受众（User Personas）及痛点底色。严禁反客为主去盘问“你要做什么受众”。
*   **Task 1.2: 竞品分析与特异性状态流追问**：基于已明确的受众做行业纵深打样。如果核心基底素材（比如是否有极其死板必须服从的母品牌 VIS 约束）在黑板遗失，立刻给黑板打上 `[提问中]` 的钢印，带走疑问强压客户拿结论。索得真理后，切回黑板修改为 `[已决断]` 给全盘打样定调。
*   **Task 1.3: 端容积与设计边界围栏**：框选跨屏幕响应式的大骨架，明确定位核心功能模块交付颗粒度的断点，为未来的组件规范图纸留好足够的扩展坞。

### Phase 2: 体验现状走查与资产盘点 (UX Audit & Design System Check)
**目标**：针对老业务进行"探雷"，并梳理现有设计资产，避免闭门造车或重复造轮子。
*   **Task 2.1: 启发式评估 (Heuristic Evaluation)**：如果是迭代老需求，走查线上现有版本的交互流，找出反人类设计、视觉债和用户操作卡点。
*   **Task 2.2: 基础信息流走查**：如果是复杂系统或表单域，根据现有的接口或数据库摸底功能模块中能获得到的真实信息。保证“画进去的数能读出来”，防止设计出前台展示丰富但后端根本没维度数据的“假把式”。
*   **Task 2.3: 设计资产池盘点 (Design Asset Review)**：翻阅团队现有的 Design System（组件库）或规范字典。明确哪些交互可以直接复用，哪些需要进行组件级创新定制。

### Phase 3: 体验探索与方向决策 (Ideation & Visual Direction)
**目标**：提供高质量的视觉与交互选型，抛出可能的方案分支，权衡利弊后敲定基调。
*   **Task 3.1: 情绪板与风格探索 (Moodboarding)**：为了和业务提前对齐视觉感受，聚合相关的视觉参考、颜色、排版和控件风格，奠定初始调性。
*   **Task 3.2: 核心交互骨架多案推演 (Option A/B)**：针对核心路径的页面（如控制台首屏或关键转化流），提供 2-3 种不同的布局或信息架构方案（通常通过低保真线框图 Wireframe 完成）。
*   **Task 3.3: 方案平衡与拍板 (Trade-off & Decision)**：与业务侧、架构/前端侧共同评估 2-3 种方案，评估各自的研发成本、视觉冲击张力、用户体验顺滑度等，最终拍板选择一条主干道推进深化。

### Phase 4: 蓝图绘制与全场景设计 (UX/UI Detailed Design)
**目标**：将确定的设计概念方向，转化为详尽的、覆盖全场景、可开发的高保真设计图纸。
*   **Task 4.1: 用户流程与信息架构地图**：提供全局且清晰的用户流向 (User Flow Map)，明确一切可能的页面流转及逻辑依赖。
*   **Task 4.2: 高保真视觉产出 (High-Fidelity UI)**：基于敲定的方向和组件库，产出主干链路（核心场景）的高保真页面，精细化推敲字号、间距、阴影、层级和品牌色应用。
*   **Task 4.3: 异常全集与场景边界设计 (Corner Cases & States)**：这是区分高阶与初级的核心分水岭。必须穷尽交付：各种初始为空态 (Empty State)、页面及组件加载态 (Skeleton/Loading)、报错断网等失败态 (Error State)、文字极端超长溢出处理机制，以及角色的无权限兜底拦截画面机制。
*   **Task 4.4: 动效与核心微交互展现 (Micro-interactions)**：制作能清晰传达交互隐喻的动效（Clickable Prototype 或更精细的 AE/Lottie 动画示例），提供诸如悬浮反应、平滑转场等给前端做标准参照。

### Phase 5: 体验风险阻断与可用性评估 (Risk Assessment & Prevention)
**目标**：在进入庞大开发排期之前，拦截那些可能对用户体感造成毁灭性打击的问题或隐患。
*   **Task 5.1: 认知负荷与死角排查**：自我走查，包括但不限于页面核心信息密度是否过高让用户感到焦躁？填表步骤流是否过重导致跳出率流失？移动设备的重点热区是否符合人体工学？
*   **Task 5.2: 无障碍与多端兼容性预案 (Accessibility & Responsiveness)**：审查核心界面的对比读写比率是否满足常规标准（WCAG 等）防患色弱人群难识别。同时，明确核心复杂功能如果从宽屏缩放到窄屏等不同断点 (Breakpoints) 布局规则及降级打法。
*   **Task 5.3: 性能与前端技术成本风险博弈**：与前端开发对齐，评估某一个极为沉浸的 3D 或大规模数据渲染交互会不会引起严重的卡顿掉帧或者大量带宽占用？是否需要针对低性能终端留有单纯的 2D 或纯图片展示 Fallback 降级。

### Phase 6: 工程交付与落地管控 (Handoff & Design QA)
**目标**：确保最终开发呈现的是“原汁原味”的设计理念，实现高比率还原并追踪回流数据指引下次迭代。
*   **Task 6.1: 规范化开发移交 (Handoff)**：系统输出符合技术流转认知的资产。例如按设备所需配比标准切图、尺寸、色值标注（通常直接经由 Figma/蓝湖等），提炼 Design Token 或更新已有系统变量，并发起给技术团队的设计图宣讲会。
*   **Task 6.2: 严格的设计还原验收 (Design QA)**：在产研链条的测试流程中，进入真实测试环境，像真实用户一样做沉浸式全流走查，揪出颜色、位移、动效时长的差异，登记体验类 Bug Issue 给开发做收拢，死守落地门槛线。
*   **Task 6.3: 线上影响效果回收与后续迭代支持**：系统上线稳定后，积极搜集业务真实数据的漏斗变化、客服反馈客诉或是相关工具产生的热力图。把它变成下一轮 Phase 1 最真实的用户洞察燃料。
