# 架构师 SOP 模版生成器 Meta-Prompt (Template Generator Prompt)

> 💡 **这不仅是一个 Prompt，这是用来“生小鸡”的母鸡（Meta-Prompt）。**
> 
> 这个 Prompt 提炼了我们之前为你生成极受好评的 `OUT-1.1` 和 `OUT-1.2` 数据模版时的**所有核心架构师心法与行文铁律**。
> 以后当你推进到了《Architect SOP》中的任意一个新节点（比如现在的 Task 1.3，或者未来的 2.1、3.2）时，你只需要在下方的 **`『这里』`** 填入具体的任务名和背景，一股脑发给大模型（我，或者其它的 Claude / GPT-4），就能瞬间得到一份极具原生专业度、带有“家族血统”结构完全统一的 `OUT-[*.X]_Template.md` 文档。

---

## 复制以下 Prompt 喂给大模型：

━━━━━━━━━━━━━━━━━━━━━━━━━━━

请你现在扮演**企业级首席架构师（Chief Architect）**和**高级 Agent 框架设计专家**。
我目前正在主导一个极高维度的【AI 架构师特工流（Architect AI Agent SOP）】。我已经梳理出了一条完整的工作链，现在需要你协助我把工作链上的每个独立阶段，具象化并沉淀为标准输出物格式模版。

目前我们进行到了 “4.1: API 与契约设计” 这一步。

请你发挥首席架构师的实力，立刻帮我原创设计出一份直接可以直接落地使用（无论是供给下游 AI Agent 解析计算，或是人类架构师复述填写）的、名为 `OUT-[任务编号]_Template.md` 的 Markdown 数据模版文件。在设计该模版框架的正文时，**你必须绝对严格、无一遗漏地遵守以下【五大排版与内容铁律】**，以保持我们此流派模版极具统治力的家族血统：

### 铁律 1：元数据与执行摘要定音 (Metadata & Executive Summary)
在模版的开篇，雷打不动地保留 `主题 (Topic)/操作人员/进度状态/生成时间` 的标准元数据声明区。紧随其后，要求用极富业务价值的一两句**“定调”**话语作为 Executive Summary（执行摘要），概括该报告输出的核心使命与最高优先级结论，绝不允许让读者看完全文才知道这阶段在干什么。

### 铁律 2：结构化高解析度矩阵设计 (Structured Matrix & MECE)
绝不允许在“需要干系人去填数据”的地方留白出供人写小作文段落的文本框。
对于此阶段所有的核心产出物清单与维度罗列，**必须被你强制转化为严苛维度的 Markdown 表格结构**（例如：特性矩阵、权衡打分表、资源水位线表等）。其设计的列首必须严格符合 MECE 原则（相互独立、完全穷尽），迫使使用者或推导 Agent 将模棱两可的定性形容词，无情量化为具象的指标。

### 铁律 3：最核心的反演——架构边界声明 (Out of Scope / Anti-Goals)
这往往是平庸架构方案与大师方案的分水岭。在模版接近尾声时（倒数第二节），你必须设立绝不可少的独立板块，去划定当前任务模块的“不可接触雷区”。
引导填写方在这里强制填入当前任务中**不支持、不扩展、绝对不涉及、禁止重构波及**的负向列表（Anti-Goals）。通过定义极简边缘，防止后续功能链的无尽蔓延。

### 铁律 4：【必须包含的终极绝招】上下文流转映射表 (Downstream I/O Mapping)
作为衔接整个巨大流转状态图的中枢，该模版的**最后一个章节必须是一张名叫“上下文数据元素向后游阶段流转的因果推证表（Downstream Output Mapping）”**。
在这张表里，你要像预言家一样，为填表人拆解：【当前本模版里刚刚确定的某张表里的某个限制条件】，在接下来将充当什么重要的高爆炸弹，会如何深远地影响乃至直接否决**下游具体哪个 Task (即哪一个 OUT-Y.Y)** 的输出和判断？
*（例如要求：告诉他们这里的某一特性限制，将会直接导致 3.X 的方案必须舍弃旧库。）*
只有这样，整个大模型的超长执行流栈谱（Call Stack）才被打通、产生了真正的自举意义。

### 铁律 6：【全新联动机制】大盘基准溯源与数据源同步标注 (Single Source of Truth Checking)
【🔥 新增的黑板交互防撞铁律】若本次要求你生成的 OUT 数据模版内本身涵盖了基础宏观指标（如预期核心 TPS、品牌基调、设备屏幕兼容范围、合规等保等），模版内绝对不能随便放一个任人填写的占位符留白。必须在对应区域内预置特殊的定界块：“**依赖 `[EXT-Master_Context_Board.md]` 大盘看板注入数据的声明**”。并强制引导未来的填表 Agent 或人类标注交代清楚：本次填写的数据究竟是从黑板老巢里直接拿现成的？还是由于大盘里漏发，自己刚刚跑去给客户发问拿定论并同时完成了反写黑板的写出动作？
### 铁律 5：存在拓扑或流程时的双模轨绘制限制 (Mermaid + Drawio Rule)
请在提供模版时加入预提示：假若在这份生成出的设计书中不可避免地牵涉到高可用网络拓扑、复杂业务分支状态机、微服务时序流等呈现，规定模版的执行人必须做到“双栖产图”：
一则是在该 Markdown 对应区块内直接强植入 `mermaid` 代码快作为默认阅览格式渲染；二则并发在对应的 `outputs/diagrams/` 同步一份脱水的 `.drawio` 图形文件并配注跨文档链接 `> See: [架构图.drawio]`，以此满足外部受众二次修改拖拽的需要。
